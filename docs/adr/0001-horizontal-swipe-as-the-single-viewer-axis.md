# 全屏消费统一为横划，竖划只保留给随机播放

> **部分被取代**：竖划已彻底废弃，下滑改作全屏返回。见 ADR-0006。
> 本文"一个播放器、图片与视频同等待遇"的核心结论仍然有效。

Web 前端演化出了两个并存的全屏播放器：点图片进横划灯箱（可缩放、有幻灯片），点视频
进竖划的抖音式播放器（不可缩放、无幻灯片）。后果是同一张图片从不同入口进去能力不同——
从视频竖划过去的图片没有缩放手势。原生客户端只实现**一个**播放器，横划切换，图片与视频
同等待遇；抖音式竖划保留，但只作为**随机播放**的呈现形式。

决定的依据是库的构成：97k 张图片 vs 1.4k 个视频，图片占 98.6%。竖划是为视频流设计的
交互，把它当作图片库的主消费方式是本末倒置。

## Consequences

- 划动轴对应的是**意图**（横划＝在找东西，竖划＝在刷）而非**内容类型**，这与"随机播放是
  动作而非视图"的领域定义一致。
- Web 前端"混合/隔离"这个设置原本用于控制竖划序列是否混入图片。在新模型下横划序列
  天然就是当前视图里的媒体顺序，该设置只对随机播放仍有意义。
- 手势系统、预加载策略、序列构建全部建立在横划轴上。改变划动轴意味着重写播放器，
  因此这个决定应当在写第一行播放器代码之前就确定。
