# 侧栏是逐层下钻的单层列表，不是树

> **部分取代 ADR-0007**：那里关于目录树的两条——"三角只展开不导航、行只导航不展开"的
> 两热区设计，以及为此手写 `LazyVStack` 而不用 `List(children:)` 的理由——不再适用。
> ADR-0007 的其余部分（四格→三格切换器、视图跟着路由走、叶子判据）仍然有效。

原来抽屉/侧栏里是一棵可展开的树：每行一个三角 + 名字，展开到哪层就缩进到哪层，
`TreeStore` 维护展开集合并在每次导航后**追加**展开当前路径的祖先。

实测（iPhone 17 Pro 模拟器，真实库）暴露了几件事：

- 三角和文件夹图标用的 `Color.secondary` 在抽屉的 `.regularMaterial` 上走 vibrancy 混合，
  压在深色照片墙上**根本不可见**。用户看到的是每行左侧一块 44pt 的空白，不知道哪些行能
  展开、点哪里。
- 三层展开后，44pt 三角列 + 14pt×深度的缩进把名字挤到右边，长名字只剩几个字。
- 展开是追加式的，跳转几次后树上同时开着好几个分支，再打开抽屉是一片乱。

这些都是"一屏里同时画多层"的必然后果，不是调参能修的。

## 决定

侧栏**永远只显示一层**：顶部一个 header（返回按钮 + 这一层的名字），下面是这一层的
子文件夹。没有缩进，没有三角，每行拿到整栏宽度。

热区分配：

| 目标 | 动作 |
|---|---|
| 行的名字 | 导航到该文件夹（有子节点进 `album`，叶子进 `image`），抽屉关闭 |
| 分支行右侧的 `›` | 侧栏下钻一层，**墙不动**，抽屉不关 |
| header 的名字 | 导航到这一层本身（"看这个文件夹底下所有相册"） |
| header 的 `‹` | 侧栏回到上一层，墙不动 |
| 根层 header | 显示"图库"，没有 `‹` |

同步规则：**任何导航发生后，侧栏层级重置为当前文件夹的父层**，当前文件夹在其中高亮。
在那之前用户手动下钻到哪就停在哪。这一条替代了原来的 `revealAncestors`。

样式上是标准 iOS 列表：hairline 行分隔线（左缩进 12pt）、裸 `›`（44pt 热区）、单行、
中间截断（名字的区分度通常在尾部）。

## 考虑过的替代

- **修树的样式**（可见的三角、28pt 三角列、20pt 缩进、去图标、加根行）。做出来看过，
  确实好一截，但多层同屏的根本问题还在，跳转后"只展开当前分支"仍要另加一套收拢逻辑。
- **点整行下钻、只能通过 header 导航到分支**（更符合 iOS 惯例：行尾 `›` 表示整行可点）。
  否掉的原因是这个库里"看 Twitter 底下所有相册"是高频动作，应当一次点击到达。惯例
  冲突靠反馈本身消解：点名字墙变了，点 `›` 侧栏往里进了。
- `›` 做成带底色的圆钮以示与惯例不同——做出来丑，撤回裸 `›`。

## Consequences

- 一次只能看到一个分支的内容，看不到两个分支同时展开。这个库主体只有三层，接受。
- `TreeStore` 的展开集合（`expanded` / `toggleExpansion` / `revealAncestors`）整块下线，
  侧栏层级变成一个路径字符串。
- macOS 侧栏用同一个组件。桌面上一棵真正的 outline 会更"原生"，但共用是偏好
  （ADR-0002），目前只为 iOS 的体验负责。
- 不要在材质背景上用 `.secondary` 画图标——它会消失。侧栏里的次级颜色一律用
  `Color.primary.opacity(…)`。
- 既有 E2E 里 `tree-disclosure:` 的语义从"展开"变成"下钻"，`tree-node:` 仍是"导航"，
  `testTreeDisclosureExpandsWithoutNavigating` 要改成断言 header 变了而墙没变。
