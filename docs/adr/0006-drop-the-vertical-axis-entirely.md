# 彻底放弃竖划切换，下滑改作全屏返回

ADR-0001 定下"横划切换、竖划留给随机顺序"。实际做出来之后这个分工被推翻：**竖划切换资源
整个废弃，切换媒体只有左右划一种方式；下滑用于关闭全屏、返回墙。**

## 这让模型更干净，而不是更复杂

ADR-0001 的核心结论（**一个播放器，图片与视频同等待遇**）完全保留，被取代的只是"竖划归随机"
这个推论。随机顺序因此退回它在 CONTEXT.md 里本来的定义——**播放序列的排列方式**——不再
捆绑任何呈现形式。

于是 CONTEXT.md 的三个正交维度（顺序 × 推进 × 窗口形态）真正正交了：划动轴不再是其中之一，
而是固定的交互约定。随机播放和原序播放走同一个左右划播放器，区别只在序列怎么排。

## Consequences

- 播放器不需要轴参数。ADR-0002 那种"为将来留参数"的做法在这里是负债不是资产——
  轴是约定，不是选项。
- **下滑与平移冲突必须显式处理**：图片放大后，下滑是平移；未放大时，下滑是返回。
  判定依据是当前缩放级别，这是个需要单测覆盖的纯逻辑。
- ADR-0001 中"竖划保留给随机播放"一句作废，以本文为准。
